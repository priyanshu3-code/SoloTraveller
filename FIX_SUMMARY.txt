PROBLEM STATEMENT
─────────────────
Dashboard charts for "Input Tokens", "Output Tokens", "Cost", and "Trace Error Rate"
remained completely empty/blank despite metrics being calculated correctly and
appearing in console output and API responses.

ROOT CAUSE
──────────
LangSmith's dashboard chart components are hard-coded to read from specific
metadata keys:
  • Charts for tokens read: run.metadata.usage_metadata.input_tokens (as INT)
  • Charts for cost read: run.metadata.estimated_cost_usd (as FLOAT)
  • Charts for error rate read: run.metadata.error_rate (as PERCENTAGE 0-100)

The old code was storing metrics in custom/wrong keys that the dashboard
components don't know how to read.

SOLUTION APPLIED
────────────────
Changed 2 locations in app.py to store metrics in the exact native format
LangSmith's dashboard components expect:

1. Location 1: call_llm() function (lines 723-736)
   ────────────────────────────────────────────────
   BEFORE: Stored tokens in flat keys (wrong location)
   AFTER:  Store tokens in usage_metadata with int type

   OLD: run_tree.metadata["input_tokens"] = prompt_tokens
   NEW: run_tree.metadata["usage_metadata"] = {
            "input_tokens": int(prompt_tokens),
            "output_tokens": int(completion_tokens),
        }

2. Location 2: process_input() function at workflow end (lines 1244-1272)
   ───────────────────────────────────────────────────────────────────────
   BEFORE: Mixed storage - some keys in flat, some nested, wrong format
   AFTER:  All metrics in correct native keys

   OLD: run_tree.metadata["input_tokens"] = aggregated_usage["input_tokens"]
        run_tree.metadata["error_rate"] = (error / total) * 100 (DECIMAL)

   NEW: run_tree.metadata["usage_metadata"] = {
            "input_tokens": int(aggregated_usage["input_tokens"]),
            "output_tokens": int(aggregated_usage["output_tokens"]),
        }
        run_tree.metadata["estimated_cost_usd"] = cost
        run_tree.metadata["error_rate"] = (error / total) * 100 (PERCENTAGE)
